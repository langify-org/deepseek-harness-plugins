# @langify-org/dsh-memory

[English](README.md) | 日本語 | [中文](README.zh.md)

DeepSeek Harness に、人の記憶と同じ作りの記憶を持たせます。起きたことは、起きたときに記録し、あとから書き換えません。分かっていること（知識）は、夜のあいだにその記録から作ります。知識は、言われたことに応じて、必要なものが思い浮かびます。記憶は Markdown のメモのディレクトリで、git に入っています。**memory** ワークスペースのエージェントが管理するので、中身を読むことも、管理の様子を見ることもでき、どの変更も取り消せます。

なぜこの作りにしたか、何を測ったか、何を試して採用しなかったかは、[DESIGN.ja.md](DESIGN.ja.md) にあります。

## 必要なもの

- Web 版（記憶の会話を作るのに使います）と、プロセス内のサブエージェントのある DSH `>=0.2.2-rc.2 <0.3.0-0`。
- ホストの `PATH` にある [`git`](https://git-scm.com)。

## 導入

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

DSH の Web 版や Desktop 版では **Plugins** ページから追加できます。

## 仕組み

起動すると、プラグインは記憶のディレクトリを git リポジトリとして作ります。すでにあるものはそのままにします。

- `AGENTS.md`：あなたの方針。記憶が何のためにあるか。すべての記憶係に渡すので、何が大事か、どの言語で書くかを伝える場所になります。最初に書いてあるのは記憶の目的で、記憶のしかたではありません。強いモデルは、何を残すかを自分で判断したほうがよく覚えるためです。いったんできたあとは、プラグインはこのファイルを変えません。
- `MEMORY.md` と、それが指すファイル：**知識**。主題ごとに分けてあります。`MEMORY.md` が索引です。
- `episodes/<day>/<conversation>.md`：**エピソード**。記録係が、1 つの会話について、ある 1 日に記録したものです。時刻と対象のイベントを見出しにして、エントリを 1 つずつ並べます。エントリの中の見出しは、2 段下げて入れます。プラグインはこれらのファイルに追記します。書き換えるものは何もありません。
- `hunches/`：前の会話で分かった、**ある種の場面でどう振る舞うか**。場面ごとに 1 ファイルで、その場面をその場で見分ける手がかり、そこで起きたこと、あなたの言葉、なぜ大事かもしれないかを書きます。夜のエージェントが書きます。会話に読ませるものではなく、その場面が来たときに見守り役が思い出させます（「読む」を参照）。
- `questions.md`：あなたに聞かないと決められないこと。何がどこで言われたかと一緒に書きます。夜のエージェントが書きます。プラグインはあなたに尋ねません。尋ねられるのは、たとえばあなたの自動化タスクです。

また、このディレクトリを **memory** ワークスペースとして登録し、記憶係が使うエージェントプリセット **Memory**（`langify-memory`）を追加します。ツールは `read`・`edit`・`apply_patch`・`glob`・`grep` で、記録係に残るのは読むための 3 つだけです。シェル、Web、サブエージェントのツールはありません。プロファイル全体のツール（MCP サーバー、ブラウザ操作など）は、このプリセットのエージェントからプラグインが隠します。システムプロンプトにあるのは、仕組みについてどの記憶係も知っておく必要のあることです。それぞれのエージェントが何をするかは、最初のメッセージの冒頭に書きます。指示のファイル、スキル、実行環境の情報は足しません。

### 記録する

memory ワークスペースには、1 日に 1 つ記憶の会話（**Memory · YYYY-MM-DD**）があり、その日の記録係を入れておきます。日が始まる `dayStartsAt` に作り、そのとき DSH が動いていなければ、その日に初めて使うときに作ります。DSH はアーカイブした会話のサブエージェントを動かさないので、アーカイブすると次に使うときに新しく作ります。過ぎた日の会話は自由にアーカイブできます。記録係は、記憶の会話を開いてヘッダーのサブエージェントのメニューから選びます。

会話のターンが終わると、プラグインは、その会話のまだ読まれていない部分を、その会話の記録係に渡します。記録係が読むのは、ユーザーとモデルが言ったこと、サブエージェントが返してきたもの（全文と、その子の会話 ID）、ツールの呼び出し、各結果の先頭です。モデルの推論と、DSH が差し込んだ文脈（指示のファイル、スキル、通知）は含めません。ただし、記憶がどの勘を思い出させたかは、名前だけ含めます。記録係の返答が、その部分のエントリです。エントリに書くのは、決まったこととその理由、分かったこととその根拠、約束したこととその期日、変わったことと変わる前の内容、そして、あなたがモデルを正したり、モデルが出したものを流したり、モデルのしたことを喜んだりしたときの、モデルがしたこととあなたの言葉、そして、記憶が勘を思い出させたときの、それが場面に合っていたかと、その結果です。プラグインは、エントリをその会話のエピソードのファイルに追記し、`Memory-Source: <session id>` の trailer を付けて commit します。そうした内容のない部分への返答は `(nothing)` で、エントリは作られません。記録係はファイルを書かないので、知識を組み替えることも上書きすることもできず、モデルの呼び出しも 1 ターンに 1 回で済みます。

会話は、その日のあいだ 1 人の記録係を持ち続けます。そのため、記録係は自分が前に何を記録したかを知っていて、それまでの履歴はプロンプトのキャッシュから読まれます。会話を初めて担当する記録係は、要るかどうかにかかわらず、最初のターンでほぼ必ず何かを記録します。そのためプラグインは交代を避け、記録係を替えるのは、その日の記憶の会話が替わったときと、文脈が `continueTokens` を超えたときだけにしています。どの会話にどの記録係が付いているかは保存するので、DSH を再起動しても変わりません。新しい記録係は、あなたの方針、`MEMORY.md` の先頭、その会話でそれまでに言われたこと（新しい側から `contextChars` 文字まで、ツールの呼び出しは除く）、記録する部分を受け取って始めます。

部分は、そのイベントの範囲を示す行（`=== events 12 to 34 ===` など）のあとから始まり、メッセージの終わりまで続きます。閉じる行がないので、会話の中で言われたことで途中で終わることがありません。記録係は一度に 1 つだけ働き、その間に終わったターンは待ちます。記録係が最後まで終えられなかった分は、その会話の次のターンで、新しい記録係が読み直します。サブエージェントの会話と、memory ワークスペースの会話は記録しません。memory ワークスペースで記録係以外の会話（そこで記憶を直接直すときなど）のターンが終わると、その返答をメッセージにして commit します。

### 固定化する

1 日に 1 回、その日の記憶の会話の最初の数ターンで、新しいエピソードの内容が知識の一部になります。それが終わるまで、記録係は待ちます。

1. **比べる。** 新しいエントリごとに、プラグインは、知識と、ほかの新しいエピソードの行から、そのエントリと共通する語が最も多いものを選びます。1 つのファイルからは 2 行までです。そして、その日の記憶のエージェントに、そのエントリがどの行と食い違い、どの行を古いものにするかを尋ねます。モデルは、2 つのメモが文脈にあるだけでは、それらを比べません。その 2 つについて尋ねられると、比べます。
2. **最新にする。** 次に、エージェントが知識を変更します。エピソードで確かになったことは、それが扱う主題のところに入れます。それは、その話が出た会話の主題とは違うことがよくあります。変わった決定や状態は、置き換えます。あるものの仕組みについての 2 つの記述が食い違うときは、どちらも残し、どちらにも食い違っていると書きます。どちらかを実物と照らして確かめるまで、そうしておきます。ある日に向けた約束は、その日の会話が目にする場所に入れます。`MEMORY.md` は短く保ちます。ある種の場面でどう振る舞うかについて会話で分かったことは、`hunches/` に入れます。手がかりはあとから分かったことではなくその場で見えたもので書き、あなたの言葉は言ったとおりに残し、理由は外れうる読みとして書きます。似た場面で同じことを期待する勘は 1 つにまとめ、違うことを期待する勘には、場面を見分ける手がかりを書き足します。あなたに聞かないと決められないことは `questions.md` に入れます。エージェントは、メモが指しているあなたのファイルと、記録係に渡した内容を読めます。記録係に渡した内容は、`transcriptDays` 日のあいだ `transcripts` にプレーンテキストで置かれます（日ごとのディレクトリ、会話ごとのファイル。記憶のディレクトリの外で、git にも入りません）。

エージェントの変更は 1 つの commit になり、そのメッセージはエージェントの返答です。固定化が最後まで終わらなかった夜のエピソードは、次の夜に回ります。そのあと、`episodeDays` 日より古いエピソードはディレクトリからなくなります。それより長く知っておくべきことは、そのときにはほかのファイルに入っていて、残りは git にあります。エージェントのモデルは `tidyProvider`・`tidyModel`・`tidyReasoningEffort` で決めます。今すぐ固定化したいときは、どの会話でも `/dream` と打ちます。memory ワークスペースの専用の会話（**Memory · dream · <日付> <時刻>**）で動き、そのあいだ記録係は待ちます。新しいエピソードがなければ、そう伝えるだけです。いつ動かしても違いはありません。固定化した位置は記録されるので、次の固定化は、そのあとに足されたエントリだけを扱います。前のエントリがあるファイルでも同じです。

### 読む

ターンの各ステップの前に、会話がまだ持っていないものを渡します。長いターンにも、途中で変更が伝わります。

- **索引**（初めてのときと、compaction で見えなくなったとき）：`MEMORY.md` の先頭（`indexLines` と `indexBytes` まで）と、まだ知識の一部になっていないエピソードのファイルの名前です。そこで、記憶は自分で管理するものではないと伝えます。伝えないと、「覚えておいて」と言われた会話が自分でファイルを書き換えるためです。索引に挙がっていないものはディレクトリを検索すると見つかる、とも伝えます。
- **変わったもの**（その後）：変わったファイルの名前です。変更の元がその会話だけのときは渡しません。
- **想起**（あなたが何か言ったとき）：言ったことに応じて必要になる行です。知識と、まだ知識の一部になっていないエピソードから選びます。まず、言ったことに出てくる名前（ラテン文字の語か、カタカナの連なり）のうち、少数の行にしかないものを含む行すべて。次に、言ったことと共通する語が最も多い行で、1 つのファイルからは 2 行までです。何の名前も挙げていない数語だけの発言からは、何も想起しません。同じ行を 1 つの会話に 2 回見せることもありません。
- **今日**（その日に初めて何か言ったとき）：その日より前に書かれた行のうち、その日の日付を挙げているものです。日付の書き方は問いません（`2026-11-16`、`11/16`、`11 月 16 日`）。
- **勘**（`watcherProvider` と `watcherModel` を指定していて、`hunches/` に何かあるとき、各ステップの前）：会話を外から見守る小さいモデルに、それまでに起きたことと、前に見てから起きたこと（あなたの発言、モデルの返答、ツールの呼び出しと結果）を、すべての勘と一緒に見せます。見守り役は、いま場面が来た勘の名前を、手がかりになった直前の言葉の引用と一緒に挙げます。会話には、その勘を夜に書かれたとおり（あなたの言葉ごと）、指示ではなく思い出したこととして渡します。見守り役は場面を見分けるだけです。自分の言葉で言わせると、思い出したことが助言に変わったためです。引用した言葉が直前に起きたことの中にない勘や、渡した勘のどれも挙げていない返答では、何も思い出させません。1 つの勘を思い出させるのは、会話にそれが見えているあいだは 1 回（compaction で見えなくなると、また思い出させます）、1 ターンでは 3 回までです。見守り役が失敗したり 10 秒を超えたりしたときは何も思い出させず、ステップはそのまま進みます。勘と `questions.md` は、想起と「今日」の行には含めません。

サブエージェントの会話と、memory ワークスペースの会話には、記憶を渡しません。

### 評価する

`eval/run.mjs` は、使い捨ての DSH のホームディレクトリで、実際のモデルを使ってケースを実行し、採点します。ケースは、出発点になる記憶、会話で言うことと新しい会話に尋ねる質問を並べた台本、答えとその後のディレクトリに対するチェックからなります。`eval/cases` のケースは架空のものです。`--cases` には自分のケースのディレクトリを渡せます。実行のしかたはファイルの冒頭に、測った内容は [DESIGN.ja.md](DESIGN.ja.md) にあります。

## 安全性

記憶係は、Memory プリセットで記憶のディレクトリで働く DSH のサブエージェントで、使えるのはファイルのツールだけです。ファイルの権限は記憶の会話のものを引き継ぐので、記憶係を記憶のディレクトリの中にとどめているのは、指示とあなたの権限モードであって、プラグインではありません。すべての会話が、そこに打ち込んだものや、モデルが読んだ Web ページも含めて記録係に送られます。記録係には、秘密を書かないこと、会話の書き出しを指示ではなく記録として扱うことを伝えています。記録係に渡した内容は、`transcriptDays` 日のあいだプレーンテキストでディスクにも残ります。見守り役を指定すると、各会話で言われたことと行われたこと、すべての勘も、各ステップの前に見守り役のモデルに送られます。ふつうの会話には、記憶は自分で管理するものではないと伝えますが、ディレクトリへの書き込みを止める仕組みはありません。DSH には、ファイルへのフルアクセスのもとで特定のディレクトリを守る手段がなく、ワークスペース内に限る権限モードなら DSH のサンドボックスがすでに止めるためです。commit を確かめてください。止めるには **Plugins** ページでプラグインを無効にします。何も消えません。記憶のディレクトリ、記憶の会話、ワークスペースは残ります。
