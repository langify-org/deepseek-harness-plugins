# @langify-org/dsh-memory

[English](README.md) | 日本語 | [中文](README.zh.md)

DeepSeek Harness に記憶を持たせます。記憶はディレクトリで、記録係のエージェントがすべての会話から更新します。記録係は **memory** ワークスペースの自分の会話で働くので、何をなぜ記憶したかを見られます。変更はすべて git の commit なので、取り消せます。

これは最初の段階です。記憶は書かれますが、会話はまだそれを読みません。

## 必要なもの

- Web 版のある DSH `>=0.2.2-rc.1 <0.3.0-0`（記録係の会話を作るのに使います）。
- ホストの `PATH` にある [`git`](https://git-scm.com)。

## 導入

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

DSH の Web 版や Desktop 版では **Plugins** ページから追加できます。

## 設定

| 設定            | 既定値             | 何か                                                   |
| --------------- | ------------------ | ------------------------------------------------------ |
| `directory`     | `$DSH_HOME/memory` | 記憶のディレクトリ                                     |
| `git`           | `git`              | git の実行ファイル。`PATH` から探す名前か、パス        |
| `timeZone`      | ホストのもの       | 記録係の会話を日ごとに分けるときの IANA のタイムゾーン |
| `toolArguments` | `300`              | 記録係が読む、ツール呼び出しの引数の文字数             |
| `toolResult`    | `500`              | 記録係が読む、ツールの結果の文字数                     |

## 仕組み

起動すると、記憶のディレクトリを git リポジトリとして作り、2 つのファイルを置きます。すでにあるファイルはそのままにします。

- `AGENTS.md`：記憶が何のためにあるか。DSH はこのディレクトリで働くすべての会話にこれを渡すので、記憶係に何が大事かを伝える場所になります。書いてあるのは記憶の目的で、記憶のしかたではありません。強いモデルは、何を残すかを自分で判断したほうがよく覚えるためです。
- `MEMORY.md`：記憶していることの索引。

また、このディレクトリを **memory** ワークスペースとして登録します。

会話のターンが終わると、記録係がまだ読んでいない部分を、その日の記録係の会話（memory ワークスペースの **Memory scribe · YYYY-MM-DD**）に送ります。その日の会話がなければ作ります。記録係が読むのは、ユーザーとモデルが言ったこと、ツールの呼び出し、各結果の先頭です。モデルの推論と、DSH が差し込んだ文脈（指示のファイル、スキル、通知）は含めません。サブエージェントの会話と、memory ワークスペースの会話は送りません。記録係が働いている間に届いた依頼は待ち、まとめて読まれます。

memory ワークスペースのどの会話でもターンが終わると、ディレクトリの変更をすべて commit します。commit メッセージはターンを終えた返答で、そのターンが読んだ会話ごとに `Memory-Source: <session id>` の trailer を付けます。何も変えなかったターンは commit しません。

## 安全性

記録係は、既定のプリセットとその権限で記憶のディレクトリで働く、ふつうの DSH の会話です。すべての会話が、そこに打ち込んだものも含めて記録係に送られます。`AGENTS.md` で秘密を書かないよう伝えていますが、commit を確かめてください。止めるには **Plugins** ページでプラグインを無効にします。何も消えません。記憶のディレクトリ、記録係の会話、ワークスペースは残ります。
