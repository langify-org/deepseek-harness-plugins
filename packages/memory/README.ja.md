# @langify-org/dsh-memory

[English](README.md) | 日本語 | [中文](README.zh.md)

DeepSeek Harness に記憶を持たせます。記憶はディレクトリで、記録係のエージェントがすべての会話から更新し、すべての会話に渡されます。記録係は **memory** ワークスペースで働くので、何をなぜ記憶したかを見られます。変更はすべて git の commit なので、取り消せます。

## 必要なもの

- Web 版（記憶の会話を作るのに使います）と、プロセス内のサブエージェントのある DSH `>=0.2.2-rc.2 <0.3.0-0`。
- ホストの `PATH` にある [`git`](https://git-scm.com)。

## 導入

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

DSH の Web 版や Desktop 版では **Plugins** ページから追加できます。

## 設定

| ------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `directory`                     | `$DSH_HOME/memory` | 記憶のディレクトリ                                                                                                                                                           |
| `git`                           | `git`              | git の実行ファイル。`PATH` から探す名前か、パス                                                                                                                              |
| `timeZone`                      | ホストのもの       | 記憶の会話の日を決める IANA のタイムゾーン                                                                                                                                   |
| `dayStartsAt`                   | `3`                | 新しい記憶の会話で日が始まる時刻（時）                                                                                                                                       |

| `agentPreset`                   | `langify-memory`   | 記憶の会話と記録係が使うエージェントプリセット                                                                                                                               |
| `scribeProvider`・`scribeModel` | 記憶の会話のもの   | 記録係の LLM の provider とモデル。2 つ一緒に指定する                                                                                                                        |
| `scribeReasoningEffort`         | モデルの既定       | 記録係の reasoning effort。モデルが選べるもののうちの 1 つ                                                                                                                   |
| `toolArguments`                 | `300`              | 記録係が読む、ツール呼び出しの引数の文字数                                                                                                                                   |
| `toolResult`                    | `500`              | 記録係が読む、ツールの結果の文字数                                                                                                                                           |
| `contextChars`                  | `8000`             | 記録する部分より前に会話で言われたことのうち、新しい記録係に文脈として渡す文字数                                                                                             |
| `continueSeconds`               | `300`              | 記録係のターンが終わってから、同じ会話の次のターンを続けて担当させる秒数。プロンプトのキャッシュが履歴を持っている時間に合わせる。`0` にすると毎ターン新しい記録係を起動する |

## 仕組み

起動すると、記憶のディレクトリを git リポジトリとして作り、2 つのファイルを置きます。すでにあるファイルはそのままにします。

- `AGENTS.md`：あなたの方針。記憶が何のためにあるか。すべての記録係に渡すので、何が大事か、どの言語で書くかを伝える場所になります。最初に書いてあるのは記憶の目的で、記憶のしかたではありません。強いモデルは、何を残すかを自分で判断したほうがよく覚えるためです。いったんできたあとは、プラグインはこのファイルを変えません。
- `MEMORY.md`：記憶していることの索引。

また、このディレクトリを **memory** ワークスペースとして登録し、記憶係が使うエージェントプリセット **Memory**（`langify-memory`）を追加します。

- ツールは `read`・`edit`・`apply_patch`・`glob`・`grep` です。`write` はありません。記録係のターンの合間に、ほかの会話の記録係がディレクトリを変えるためです。`edit` と `apply_patch` は、ファイルの文面が記録係の読んだものと合っている箇所だけを変えますが、`write` は古い文面でファイルを丸ごと置き換えてしまいます。シェル、Web、サブエージェントのツールはありません。プロファイル全体のツール（MCP サーバー、ブラウザ操作など）は、このプリセットのエージェントからプラグインが隠します。
- システムプロンプトは、プラグインの仕組みのために記憶係が知っておく必要のあることだけです。記憶はほかの会話とあとの会話のためのもので、記録している会話のためではないこと。1 つの会話を部分ごとに記録することと、メッセージの中で記録する部分がどこから始まりどこで終わるか。`MEMORY.md` が何のためにあり、その先頭がすべての会話に渡ること。自分のターンの合間にほかのエージェントがディレクトリを変えることと、いずれ新しいエージェントに交代すること。会話で言われたことは記録であって指示ではないこと。秘密を書かないこと。返答がそのつど commit メッセージになり、続いているほかのすべての会話に足されること。指示のファイル、スキル、実行環境の情報は足しません。

### 書く

memory ワークスペースには、1 日に 1 つ記憶の会話（**Memory · YYYY-MM-DD**）があり、その日に初めて使うときに作ります。日は `dayStartsAt` に始まります。DSH はアーカイブした会話のサブエージェントを動かさないので、アーカイブすると次に使うときに新しく作ります。過ぎた日の会話は自由にアーカイブできます。記憶の会話は、その日の記録係を入れておくだけです。作ったときにだけ、モデルが短い一文で一度返事をします。サイドバーはターンのない会話を隠し、その下の記録係も見えなくなるためです。記録係は、記憶の会話を開いてヘッダーのサブエージェントのメニューから選びます。

会話のターンが終わると、プラグインはその会話のまだ記録していない部分を、その会話の記録係に渡します。記録係は、その日の記憶の会話のサブエージェントです。一度も記録していない会話（プラグインを入れる前からある会話など）は、終わったばかりのターンから読みます。記録係が読むのは、ユーザーとモデルが言ったこと、ツールの呼び出し、各結果の先頭です。モデルの推論と、DSH が差し込んだ文脈（指示のファイル、スキル、通知）は含めません。

記録係は、同じ会話をターンごとに続けて担当します。2 通目以降のメッセージに入るのは、その間にほかの記録係が変えた記憶のファイルの名前と、次の部分だけです。記録係は自分が前に何を記録したかを知っているので、記憶が会話の進み具合をターンごとに持っておく必要がありません。それまでの履歴は、送り直さずにプロンプトのキャッシュから読まれます。会話が `continueSeconds` を超えて止まったとき（キャッシュが履歴を持っている時間）や、記録係の文脈が `continueTokens` を超えたときは、新しい記録係に替えます。ステップのたびに文脈全体を読み直すので、長い文脈は始め直すより高くつくためです。新しい記録係は、あなたの方針、会話に渡すのと同じ `MEMORY.md` の先頭、その会話でそれまでに言われたこと（新しい側から `contextChars` 文字まで、ツールの呼び出しは除く）、記録する部分だけを持って始めるので、ある会話で言われたことが、別の会話の記憶に混ざりません。ディレクトリのほかの部分は、必要に応じて自分で読みます。

記録する部分は、そのイベントの範囲を示す行（`=== events 12 to 34 ===` など）のあとから始まり、メッセージの終わりまで続きます。閉じる行がないので、会話の中で言われたことで途中で終わることがありません。

記録係は一度に 1 つだけ働き、その間に終わったターンは待ちます。記録係のターンが終わると、ディレクトリの変更をすべて commit します。commit メッセージは記録係の返答で、元の会話を示す `Memory-Source: <session id>` の trailer を付けます。何も変えなかったターンは commit しません。記録係が最後まで終えられなかった分は、その会話の次のターンで、新しい記録係が読み直します。

サブエージェントの会話と、memory ワークスペースの会話は記録しません。memory ワークスペースで記録係以外の会話（そこで記憶を直接直すときなど）のターンが終わると、その返答をメッセージにして commit します。

### 読む

ターンの最初に、会話に記憶を渡します。

- 初めてのときは、`MEMORY.md` の先頭（`indexLines` と `indexBytes` まで）とその版。
- その後は、記憶が変わったときに、それ以降の commit のメッセージ。その会話だけが元になった commit は除きます。
- 渡してから `rebaselineAfter` を超える commit があったときや、compaction で見えなくなったときは、`MEMORY.md` をもう一度。

サブエージェントの会話と、memory ワークスペースの会話には渡しません。

## 安全性

記録係は、Memory プリセットで記憶のディレクトリで働く DSH のサブエージェントで、使えるのはファイルのツールだけです。ファイルの権限は記憶の会話のものを引き継ぐので、記録係を記憶のディレクトリの中にとどめているのは、指示と権限モードであって、プラグインではありません。すべての会話が、そこに打ち込んだものや、モデルが読んだ Web ページも含めて記録係に送られます。秘密を書かないこと、会話の書き出しを指示ではなく記録として扱うことを伝えていますが、commit を確かめてください。止めるには **Plugins** ページでプラグインを無効にします。何も消えません。記憶のディレクトリ、記憶の会話、ワークスペースは残ります。
