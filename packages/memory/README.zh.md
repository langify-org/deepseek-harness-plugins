# @langify-org/dsh-memory

[English](README.md) | [日本語](README.ja.md) | 中文

为 DeepSeek Harness 提供记忆：一个目录，由记录员代理根据每个对话保持更新，并提供给每个对话。记录员在 **memory** 工作区中工作，因此你可以看到它们记住了什么以及原因；每次改动都是一个可撤销的 git 提交。

## 要求

- 带 Web 应用（用于创建记忆对话）和进程内子代理的 DSH `>=0.2.2-rc.2 <0.3.0-0`。
- 主机 `PATH` 中的 [`git`](https://git-scm.com)。

## 安装

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

在 DSH 的 Web 版和 Desktop 版中，可以从 **Plugins** 页面添加。

## 设置

| 设置               | 默认值             | 说明                                                     |
| ------------------ | ------------------ | -------------------------------------------------------- |
| `directory`        | `$DSH_HOME/memory` | 记忆目录                                                 |
| `git`              | `git`              | git 可执行文件：在 `PATH` 中查找的名称或路径             |
| `timeZone`         | 主机的时区         | 决定记忆对话日期的 IANA 时区                             |
| `dayStartsAt`      | `3`                | 新的记忆对话开始一天的时刻（小时）                       |
| `subagentProvider` | `spawn`            | 启动记录员的子代理 provider                              |
| `agentPreset`      | `langify-memory`   | 记忆对话及其记录员使用的代理预设                         |
| `toolArguments`    | `300`              | 记录员读取的工具调用参数的字符数                         |
| `toolResult`       | `500`              | 记录员读取的工具结果的字符数                             |
| `contextChars`     | `8000`             | 待记录部分之前的对话内容中，作为上下文交给记录员的字符数 |
| `indexLines`       | `200`              | 对话开始时提供的 `MEMORY.md` 行数                        |
| `indexBytes`       | `25600`            | 对话开始时提供的 `MEMORY.md` 字节数                      |
| `rebaselineAfter`  | `20`               | 超过这么多提交后，重新提供 `MEMORY.md`                   |

## 工作方式

启动时，插件将记忆目录创建为 git 仓库并放入两个文件，已存在的文件保持不变：

- `AGENTS.md`：你的方针，即记忆的用途。每个记录员都会收到它，因此这里是说明什么对你重要、用哪种语言书写的地方。它最初写的是记忆的用途，而不是记忆的方法：强大的模型自己判断什么值得保留时，记得更好。文件一旦存在，插件就不会再修改它。
- `MEMORY.md`：已记住内容的索引。

插件还会将该目录注册为 **memory** 工作区，并添加记忆代理使用的代理预设 **Memory**（`langify-memory`）：

- 工具只有 `read`、`write`、`edit`、`apply_patch`、`glob` 和 `grep`。没有 shell、Web 或子代理工具；配置文件的全局工具（MCP 服务器、浏览器控制等）由插件对该预设的代理隐藏。
- 系统提示词只包含插件机制需要记忆代理知道的内容：记忆是为其他对话和以后的对话准备的，而不是为正在记录的对话；每一轮之后都会被调用；`MEMORY.md` 的用途以及每个对话都会收到其开头；对话记录是记录而非指令、绝不写入机密、其回复会成为提交信息，并被添加到其他所有仍在继续的对话中。不会添加指令文件、技能或运行环境信息。

### 写入

memory 工作区中每天有一个记忆对话（**Memory · YYYY-MM-DD**），在当天第一次使用时创建；一天从 `dayStartsAt` 开始。DSH 不会运行已归档对话的子代理，因此归档后会在下次使用时新建一个；过去日期的对话可以随意归档。记忆对话只容纳当天的记录员。创建时，模型只会用一句简短的话回复一次：侧边栏会隐藏没有任何一轮的对话，其中的记录员也会随之不可见。打开记忆对话，从其标题栏的子代理菜单中选择记录员。

当某个对话的一轮结束时，插件会作为当天记忆对话的子代理启动一个记录员，并把该对话尚未记录的部分交给它。从未记录过的对话（例如安装插件之前就有的对话）从刚结束的那一轮开始读取。记录员读取的是你和模型说的话、工具调用以及每个结果的开头；模型的推论和 DSH 注入的上下文（指令文件、技能、通知）不包括在内。每个记录员开始时只有你的方针、与对话所获相同的 `MEMORY.md` 开头、该对话此前说过的内容（从最新的一侧取最多 `contextChars` 个字符，不含工具调用）以及对话记录，因此一个对话中说的内容不会混入另一个对话的记忆。提供此前说过的内容，是为了让记录员即使面对简短的“OK”这样的记录也能跟上对话，记忆也就不必逐轮保存对话的进度。目录的其余部分由它按需读取。

同一时间只有一个记录员工作，期间结束的轮次会等待。记录员结束后，插件会提交目录中的所有改动。提交信息就是记录员的回复，并附上指明来源对话的 `Memory-Source: <session id>` 尾注。没有任何改动的记录员不会产生提交。未完成的记录员负责的部分，会在该对话的下一轮重新读取。

子代理的对话和 memory 工作区中的对话不会被记录。memory 工作区中记录员以外的对话（例如你在那里直接修改记忆）的一轮结束时，会以其回复作为信息进行提交。

### 读取

在一轮开始时，对话会获得记忆：

- 第一次时，获得 `MEMORY.md` 的开头（不超过 `indexLines` 和 `indexBytes`）及其版本。
- 之后当记忆发生变化时，获得此后提交的信息；仅以该对话本身为来源的提交除外。
- 自上次提供以来的提交超过 `rebaselineAfter`，或压缩使其不可见时，再次获得 `MEMORY.md`。

子代理的对话和 memory 工作区的对话不会获得记忆。

## 安全

记录员是使用 Memory 预设的 DSH 子代理，在记忆目录中工作，只能使用文件工具。它们的文件权限继承自记忆对话，因此把它们限制在记忆目录内的是指令和你的权限模式，而不是插件。每个对话都会发送给它们，包括你在其中输入的任何内容以及模型读过的网页；它们被要求绝不写入机密，并把对话记录当作记录而非指令。请检查它们的提交。要停止插件，请在 **Plugins** 页面禁用它。不会删除任何东西：记忆目录、记忆对话和工作区都会保留。
