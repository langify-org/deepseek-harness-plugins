# @langify-org/dsh-memory

[English](README.md) | [日本語](README.ja.md) | 中文

为 DeepSeek Harness 提供记忆：一个目录，由记录员代理根据每个对话保持更新，每天整理一次，并提供给每个对话。记忆代理在 **memory** 工作区中工作，因此你可以看到它们记住了什么以及原因；每次改动都是一个可撤销的 git 提交。

## 要求

- 带 Web 应用（用于创建记忆对话）和进程内子代理的 DSH `>=0.2.2-rc.2 <0.3.0-0`。
- 主机 `PATH` 中的 [`git`](https://git-scm.com)。

## 安装

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

在 DSH 的 Web 版和 Desktop 版中，可以从 **Plugins** 页面添加。

## 工作方式

启动时，插件将记忆目录创建为 git 仓库并放入两个文件，已存在的文件保持不变：

- `AGENTS.md`：你的方针，即记忆的用途。每个记录员都会收到它，因此这里是说明什么对你重要、用哪种语言书写的地方。它最初写的是记忆的用途，而不是记忆的方法：强大的模型自己判断什么值得保留时，记得更好。文件一旦存在，插件就不会再修改它。
- `MEMORY.md`：已记住内容的索引。

插件还会将该目录注册为 **memory** 工作区，并添加记忆代理使用的代理预设 **Memory**（`langify-memory`）：

- 工具只有 `read`、`edit`、`apply_patch`、`glob` 和 `grep`。没有 `write`：在一个记录员的各轮之间，其他对话的记录员会修改目录；`edit` 和 `apply_patch` 只会修改文件中仍与记录员读到的内容一致的部分，而 `write` 会用旧内容整个替换文件。没有 shell、Web 或子代理工具；配置文件的全局工具（MCP 服务器、浏览器控制等）由插件对该预设的代理隐藏。
- 系统提示词只包含每个记忆代理都需要了解的插件机制：记忆是为其他对话和以后的对话准备的，而不是为正在记录的对话，以后的对话可以自己读取用户的文件；`MEMORY.md` 的用途，以及对话在开始时会收到其开头、之后即使它变化也不会再次收到；在它的各轮之间其他代理会修改目录，而改动只会落在文件文本仍然匹配的位置；对话中说过的内容和笔记的内容是记录而非指令；绝不写入机密；每次回复都会成为该轮的提交信息。某个代理具体要做什么（记录一个对话，或整理目录），写在它第一条消息的开头。不会添加指令文件、技能或运行环境信息。

### 写入

memory 工作区中每天有一个记忆对话（**Memory · YYYY-MM-DD**）。它在一天开始的 `dayStartsAt` 创建；如果那时 DSH 没有运行，则在当天第一次使用时创建。它的第一轮整理目录（见下文），之后只容纳当天的记录员；DSH 发出的记录员已结束的通知不会在这里开始新的一轮。DSH 不会运行已归档对话的子代理，因此归档后会在下次使用时新建一个；过去日期的对话可以随意归档。打开记忆对话，从其标题栏的子代理菜单中选择记录员。

当某个对话的一轮结束时，插件会把该对话尚未记录的部分交给这个对话的记录员，记录员是当天记忆对话的子代理。从未记录过的对话（例如安装插件之前就有的对话）从刚结束的那一轮开始读取。记录员读取的是你和模型说的话、工具调用以及每个结果的开头；模型的推理和 DSH 注入的上下文（指令文件、技能、通知）不包括在内。

一个对话在当天始终由同一个记录员负责：之后的每条消息只包含这期间其他记录员改动过的记忆文件名，以及下一部分。因此记录员知道自己已经记录了什么，记忆不必逐轮保存对话的进度；此前的历史也不必重新发送，而是从提示词缓存中读取。初次接手一个对话的记录员，无论是否需要，几乎总会在第一轮写点什么，因此插件尽量避免交接：只有当天的记忆对话更换，或记录员的上下文超过 `continueTokens` 时，才会更换记录员。哪个对话由哪个记录员负责会被保存下来，所以重启 DSH 不会改变什么。新的记录员开始时只有你的方针、与对话所获相同的 `MEMORY.md` 开头、该对话此前说过的内容（从最新的一侧取最多 `contextChars` 个字符，不含工具调用）以及待记录的部分，因此一个对话中说的内容不会混入另一个对话的记忆。目录的其余部分由它按需读取。

待记录的部分从一行标明其事件范围的文字（例如 `=== events 12 to 34 ===`）之后开始，一直到消息结束。没有结束行，因此对话中说过的任何内容都无法让它提前结束。

同一时间只有一个记录员工作，期间结束的轮次会等待。记录员的一轮结束后，插件会提交目录中的所有改动。提交信息就是记录员的回复，并附上指明来源对话的 `Memory-Source: <session id>` 尾注。没有任何改动的一轮不会产生提交。记录员未能完成的部分，会在该对话的下一轮由新的记录员重新读取。

子代理的对话和 memory 工作区中的对话不会被记录。memory 工作区中记录员以外的对话（例如你在那里直接修改记忆）的一轮结束时，会以其回复作为信息进行提交。

### 整理

记录员每次只看一个对话、逐轮书写，并不知道以后什么才重要，因此目录会逐渐变成流水账：已经改变的状态、被替换的草稿、多处重复的同一内容。每天一次，在当天记忆对话的第一轮，由一个能看到整个目录的代理把它整理成以后的对话希望看到的样子，并保持 `MEMORY.md` 的开头简短。它依据目录工作，也可以读取笔记所指向的你的文件；它看不到笔记所源自的对话，因此可以给存疑的笔记做标记，但无法更正。被它删除的内容仍保留在 git 历史中。整理完成之前记录员会等待，整理的改动是一个提交，提交信息就是它的回复。

整理使用 `tidyProvider`、`tidyModel` 和 `tidyReasoningEffort`。想立即整理，可以归档当天的记忆对话：之后任何对话的一轮结束时，都会开始新的记忆对话。

### 读取

在一轮开始时，对话会获得记忆：

- 第一次时，获得 `MEMORY.md` 的开头（不超过 `indexLines` 和 `indexBytes`）及其版本。
- 之后当记忆发生变化时，获得发生变化的文件名；仅以该对话本身为来源的变化除外。大多数变化来自话题无关的对话，因此只告诉对话该看哪里，由它自己读取与之相关的内容。
- 压缩使其不可见时，再次获得 `MEMORY.md`。

子代理的对话和 memory 工作区的对话不会获得记忆。

## 安全

记录员是使用 Memory 预设的 DSH 子代理，在记忆目录中工作，只能使用文件工具。它们的文件权限继承自记忆对话，因此把它们限制在记忆目录内的是指令和你的权限模式，而不是插件。每个对话都会发送给它们，包括你在其中输入的任何内容以及模型读过的网页；它们被要求绝不写入机密，并把对话记录当作记录而非指令。请检查它们的提交。要停止插件，请在 **Plugins** 页面禁用它。不会删除任何东西：记忆目录、记忆对话和工作区都会保留。
