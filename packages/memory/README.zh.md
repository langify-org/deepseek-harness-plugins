# @langify-org/dsh-memory

[English](README.md) | [日本語](README.ja.md) | 中文

为 DeepSeek Harness 提供一种像人的记忆那样构建的记忆：发生的事在发生时被记录下来，此后不再改写；已知的内容（知识）每晚由这些记录生成；当说到的话需要某项知识时，它就会浮现出来。记忆是一个放在 git 中的 Markdown 笔记目录，由 **memory** 工作区中的代理维护，因此你可以阅读它、看着它被维护，并撤销任何改动。

为什么这样构建、测量了什么、尝试过哪些做法又没有采用：见 [DESIGN.zh.md](DESIGN.zh.md)。

## 要求

- 带 Web 应用（用于创建记忆对话）和进程内子代理的 DSH `>=0.2.2-rc.2 <0.3.0-0`。
- 主机 `PATH` 中的 [`git`](https://git-scm.com)。

## 安装

```sh
dsh plugin --profile <profile> add @langify-org/dsh-memory
```

在 DSH 的 Web 版和 Desktop 版中，可以从 **Plugins** 页面添加。

## 工作方式

启动时，插件将记忆目录创建为 git 仓库，已存在的内容保持不变：

- `AGENTS.md`：你的方针，即记忆的用途。每个记忆代理都会收到它，因此这里是说明什么对你重要、用哪种语言书写的地方。它最初写的是记忆的用途，而不是记忆的方法：强大的模型自己判断什么值得保留时，记得更好。文件一旦存在，插件就不会再修改它。
- `MEMORY.md` 及其指向的文件：**知识**，按主题组织。`MEMORY.md` 是索引。
- `episodes/<day>/<conversation>.md`：**事件记录**。记录员在一天里就一个对话所记录的内容，一个条目接一个条目，每个条目都写在一个给出时间和所涉及事件的标题之下；条目自身的标题会下移两级。插件只向这些文件追加内容，没有任何东西会改写它们。
- `hunches/`：以往的对话教会的**在某类时刻该怎么做**（直觉），每类时刻一个文件：在当下就能认出这类时刻的线索、当时发生了什么、你的原话，以及它为什么可能重要。由夜间代理撰写。不会交给对话去读；当它的时刻到来时，由旁观者唤起（见“读取”）。
- `questions.md`：不问你就无法确定的事，附上说了什么、在哪里说的。由夜间代理撰写。插件本身不会向你提问；例如你的定时任务可以。

插件还会将该目录注册为 **memory** 工作区，并添加记忆代理使用的代理预设 **Memory**（`langify-memory`）。它的工具是 `read`、`edit`、`apply_patch`、`glob` 和 `grep`，留给记录员的只有其中用于读取的三个：没有 shell、Web 或子代理工具，配置文件的全局工具（MCP 服务器、浏览器控制等）由插件对该预设的代理隐藏。它的系统提示词包含每个记忆代理都需要了解的机制；某个代理具体要做什么，写在它第一条消息的开头。不会添加指令文件、技能或运行环境信息。

### 记录

memory 工作区中每天有一个记忆对话（**Memory · YYYY-MM-DD**），用来容纳当天的记录员。它在一天开始的 `dayStartsAt` 创建；如果那时 DSH 没有运行，则在当天第一次使用时创建。DSH 不会运行已归档对话的子代理，因此归档后会在下次使用时新建一个；过去日期的对话可以随意归档。打开记忆对话，从其标题栏的子代理菜单中选择记录员。

当某个对话的一轮结束时，插件会把该对话尚未读取的部分交给这个对话的记录员。记录员读取的是你和模型说的话、子代理返回的内容（全文，附子代理的会话 ID）、工具调用以及每个结果的开头；模型的推理和 DSH 注入的上下文（指令文件、技能、通知）不包括在内，但记忆唤起了哪些直觉会按名称保留。它的回复就是这一部分的条目：决定了什么、为什么；了解到了什么、是怎么知道的；承诺了什么、针对哪一天；什么变了、原来是什么；以及当你纠正模型、略过它提出的东西或对它做的事感到满意时，它做了什么和你的原话；还有记忆唤起某条直觉时，它是否契合当时的时刻、结果如何。插件把条目追加到该对话的事件记录文件中并提交，同时附上 `Memory-Source: <session id>` 尾注。不含这类内容的部分得到的回复是 `(nothing)`，不产生条目。记录员不写任何文件，因此既不能重组知识，也不能覆盖它：它每轮只需一次模型调用。

一个对话在当天始终由同一个记录员负责，因此记录员知道自己已经记录了什么，它的历史也从提示词缓存中读取。初次接手一个对话的记录员，无论是否需要，几乎总会在第一轮记录点什么，因此插件尽量避免交接：只有当天的记忆对话更换，或记录员的上下文超过 `continueTokens` 时，才会更换记录员。哪个对话由哪个记录员负责会被保存下来，所以重启 DSH 不会改变什么。新的记录员从你的方针、`MEMORY.md` 的开头、该对话此前说过的内容（从最新的一侧取最多 `contextChars` 个字符，不含工具调用）以及待记录的部分开始。

一个部分从一行标明其事件范围的文字（例如 `=== events 12 to 34 ===`）之后开始，一直到消息结束。没有结束行，因此对话中说过的任何内容都无法让它提前结束。同一时间只有一个记录员工作，期间结束的轮次会等待。记录员未能完成的部分，会在该对话的下一轮由新的记录员重新读取。子代理的对话和 memory 工作区中的对话不会被记录。memory 工作区中记录员以外的对话（例如你在那里直接修改记忆）的一轮结束时，会以其回复作为信息进行提交。

### 巩固

每天一次，在当天记忆对话的最初几轮中，新的事件记录所含的内容成为知识的一部分。在这完成之前，记录员会等待。

1. **比较。** 对每个新条目，插件从知识和其他新的事件记录中挑出与它共有词语最多的行，每个文件最多两行，然后询问当天的记忆代理：该条目与其中哪些行不一致，或使哪些行过时。模型仅仅在上下文中有两条笔记时，并不会比较它们；就这一对提问时，它才会比较。
2. **更新。** 接着，代理修改知识：事件记录所确立的内容归到它所涉及的主题之下，而这往往不是它被提到的那个对话的主题；发生了变化的决定或状态被替换；关于某个东西如何运作的两条说法不一致时，两条都保留，并且都注明这一点，直到其中一条对照实物得到核实；为某一天承诺的事，放在那一天的对话会看到的地方；`MEMORY.md` 保持简短。对话中学到的、关于在某类时刻该怎么做的内容放进 `hunches/`：线索按当下能看到的样子写，而不是事后才明白的样子；你的话照原样保留；理由作为可能出错的解读来写。在相似时刻期待相同的直觉合并为一个；期待不同的直觉，则补上能区分其时刻的线索。不问你就无法确定的事放进 `questions.md`。它可以读取笔记所指向的你的文件，也可以读取交给记录员的内容，这些内容以纯文本在 `transcripts` 中保留 `transcriptDays` 天（每天一个目录，每个对话一个文件，位于记忆目录之外，也不进入 git）。

它的改动是一个提交，提交信息就是它的回复。没有完成的那一夜，其事件记录留给下一夜。随后，超过 `episodeDays` 天的事件记录会从目录中移出；需要知道得更久的内容，那时已经在其他文件中，其余的在 git 里。该代理使用 `tidyProvider`、`tidyModel` 和 `tidyReasoningEffort` 运行。想立即巩固，在任意对话中输入 `/dream`。它在 memory 工作区中一个单独的对话（**Memory · dream · <日期> <时间>**）里运行，期间记录员会等待；如果没有新的事件记录，它只会说明这一点。什么时候运行都没有区别：已巩固到的位置会被记下，下一次只处理之后新增的条目，即使所在的文件里已有更早的条目。

### 读取

在一轮的每一步之前，对话会获得它还没有的内容，因此较长的一轮在进行中也会得知变化：

- **索引**（第一次时，以及压缩使其不可见时再次提供）：`MEMORY.md` 的开头（不超过 `indexLines` 和 `indexBytes`），以及尚未成为知识一部分的事件记录文件的名称。同时会告知它：记忆不由它自己维护，否则当你说“记住这个”时，对话会自己去改文件；还会告知它，索引没有列出的内容，搜索目录就能找到。
- **变化的内容**（此后）：发生变化的文件名；仅以该对话本身为来源的变化除外。
- **回忆**（当你说了什么时）：你所说的话需要用到的行，取自知识和尚未成为知识一部分的事件记录。先是包含其中某个名称（拉丁字母的词或一串片假名）的所有行，前提是这个名称只在少数行中出现；然后是与你所说的话共有词语最多的行，每个文件最多两行。没有指称任何东西的寥寥数语不会引出任何回忆，同一行也不会向一个对话显示两次。
- **今天**（你在某一天第一次说话时）：在那一天之前写下、提到当天日期的行，不论日期怎么写（`2026-11-16`、`11/16`、`11 月 16 日`）。
- **直觉**（设置了 `watcherProvider` 和 `watcherModel` 且 `hunches/` 中有内容时，在每一步之前）：一个从外部旁观对话的小模型会看到此前发生的事，以及它上次查看之后发生的事（你说的话、模型的回复、工具调用和结果），连同所有直觉；它写出刚刚到来的时刻所对应的直觉的名称，并引用刚刚发生的事中作为线索的原话。对话收到的是夜间写下的直觉原文（连同你的原话），作为回想，而不是指令：旁观者只负责认出时刻，因为让它用自己的话说，回想会变成建议。引用的原话不在刚刚发生的事中的直觉，以及没有提到任何给定直觉的回复，都不会唤起任何东西；一条直觉在一个对话中只唤起一次，一轮最多三次；旁观者失败或超过 10 秒时不唤起任何东西，这一步照常进行。直觉和 `questions.md` 不会出现在回忆和“今天”的行中。

子代理的对话和 memory 工作区的对话不会获得记忆。

### 评估

`eval/run.mjs` 在一次性的 DSH 主目录中用真实模型运行用例并评分：一个用例包括作为起点的记忆、一份脚本（在对话中说的话，以及向新对话提出的问题），以及对回答和之后目录的检查。`eval/cases` 中的用例是虚构的；`--cases` 可以指定你自己的用例目录。运行方法见该文件开头，测量结果见 [DESIGN.zh.md](DESIGN.zh.md)。

## 安全

记忆代理是使用 Memory 预设的 DSH 子代理，在记忆目录中工作，只能使用文件工具。它们的文件权限继承自记忆对话，因此把它们限制在记忆目录内的是指令和你的权限模式，而不是插件。每个对话都会发送给记录员，包括你在其中输入的任何内容以及模型读过的网页；记录员被要求绝不写入机密，并把对话记录当作记录而非指令。交给它们的内容还会以纯文本在磁盘上保留 `transcriptDays` 天。设置了旁观者时，每个对话所说和所做的事以及所有直觉，也会在每一步之前发送给旁观者的模型。普通对话会被告知记忆不由它自己维护，但没有机制阻止它写入该目录：在完全文件访问权限下，DSH 无法保护某个目录；而在限定于工作区的权限模式下，DSH 的沙箱本来就会阻止。请检查提交。要停止插件，请在 **Plugins** 页面禁用它。不会删除任何东西：记忆目录、记忆对话和工作区都会保留。
