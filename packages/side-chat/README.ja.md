# @langify-org/dsh-side-chat

[English](README.md) | 日本語 | [中文](README.zh.md)

DeepSeek Harness の会話を止めずに、その会話について横で質問できます。サイドチャットは会話を fork したもので、右サイドバーに DSH 自身のチャットと入力欄で開き、サイドチャットであることがモデルに伝えられます。

## 必要なもの

- Web UI のある DSH `>=0.2.1-rc.3 <0.3.0-0`。

## 導入

```sh
dsh plugin --profile <profile> add @langify-org/dsh-side-chat
```

DSH の Web 版や Desktop 版では **Plugins** ページから追加できます。

## 使い方

assistant のメッセージの下にあるボタンの列で、サイドチャットのボタンを押します。会話が fork されて `サイドチャット: <会話のタイトル>` という名前が付き、右サイドバーに開くので、普通の会話と同じように話せます。セッション一覧でサイドチャットを選ぶと、元の会話が開き、その横にサイドチャットが開きます。

- サイドチャットは、どのメッセージで押しても、会話の最後に終わった turn から始まります。メインの会話のその後の turn は届かず、サイドチャットの内容もメインの会話には届きません。
- モデルに、サイドチャットであること、メインの作業を再開せず質問に答えること、サイドチャットで頼まれない限り変更を加えないことを伝えます。この指示はチャットには表示されません。

## 仕組み

ホスト側のプラグインは、DSH の session controller でセッションを fork します（**Fork** の操作と同じ fork です）。そのすぐあとに、サイドチャットの指示を `agent.inject` で fork の inbox に入れます。指示は最初のメッセージと一緒にモデルに届きます。inbox は変わった時点でログに書かれるので、fork は作った瞬間からサイドチャットとして印が付き、再起動しても残ります。セッションの projection `langifySideChat` が、fork 自身のログからこの印を読み取り、セッション一覧を通してどのブラウザーにも届けます。ブラウザー側は、fork を自前の右サイドバーのタブで開きます。タブの中身は DSH 共通の `conversation.content` を Chat 表示で描いたもので、DSH の subagent のタブと同じ埋め込み方です。fork は普通のセッションなので、メッセージは普通の送信の経路で届きます。

## 既知の制約

- **サイドバーに並ぶ**：サイドチャットは普通のセッションなので、セッション一覧に出ます。使い終わったらアーカイブしてください。
- **最新の turn からだけ**：サイドチャットは最後に終わった turn から始まります。前のメッセージから始めることは、まだできません。

## ブラウザーでの確認

リポジトリのルートで `pnpm dev` を実行し、終わった turn が 1 つ以上ある会話で次を確かめます。

1. assistant のメッセージの下にあるサイドチャットのボタンを押す。右サイドバーに、空の入力欄のある **サイドチャット** のタブが開く。
2. 会話についての質問を送る。会話の内容を踏まえて答える。
3. メインの会話に何も増えていない。
4. サイドチャットの指示がサイドチャットに表示されず、fork の Trajectory 表示には出ている。
