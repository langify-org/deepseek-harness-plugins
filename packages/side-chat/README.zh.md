# @langify-org/dsh-side-chat

[English](README.md) | [日本語](README.ja.md) | 中文

在不打断 DeepSeek Harness 对话的情况下，就该对话在旁边提问。旁路对话是对话的一个 fork，以 DSH 自带的对话界面和输入框在右侧边栏中打开，并告知模型它处于旁路对话中。

## 环境要求

- 带 Web UI 的 DSH `>=0.2.2-rc.1 <0.3.0-0`。

## 安装

```sh
dsh plugin --profile <profile> add @langify-org/dsh-side-chat
```

在 DSH Web 版和 Desktop 版中也可以通过 **Plugins** 页面添加。

## 使用

点击 assistant 消息操作栏中的旁路对话按钮，或右侧边栏引导页中的 **旁路对话**。对话会被 fork，命名为 `旁路对话: <对话标题>`，并在右侧边栏中打开，可以像普通对话一样交谈。在会话列表中选择旁路对话时，会打开其来源对话，并在旁边打开该旁路对话。

- 无论点击哪条消息，旁路对话都从对话最近一个已完成的轮次开始。主对话之后的轮次不会传入，旁路对话的内容也不会传到主对话。
- 模型会被告知它处于旁路对话中：回答问题而不是继续主任务，除非在旁路对话中被要求，否则不做任何修改。这条指示不会显示在对话中。

## 工作原理

Host 端插件通过 DSH 的 session controller fork 会话（与 **Fork** 操作相同），随即用 `agent.inject` 把旁路对话的指示放入 fork 的 inbox，指示会随第一条消息到达模型。inbox 一变化就写入日志，因此 fork 从创建起就带有旁路对话的标记，重启后依然保留。会话 projection `langifySideChat` 从 fork 自身的日志中读取该标记，并随会话列表送达每个浏览器。浏览器端在自己的右侧边栏标签页中打开 fork，标签页以 Chat 视图渲染 DSH 共用的 `conversation.content`，嵌入方式与 DSH 的 subagent 标签页相同。fork 是普通会话，消息走普通的发送路径。

## 已知限制

- **出现在侧边栏中**：旁路对话是普通会话，会出现在会话列表中。用完后请归档。
- **只能从最新轮次开始**：旁路对话从最近一个已完成的轮次开始，暂时不能从更早的消息开始。

## 在浏览器中验证

在仓库根目录运行 `pnpm dev`，然后在至少有一个已完成轮次的对话中确认：

1. 点击 assistant 消息下方的旁路对话按钮，右侧边栏打开带有空输入框的 **旁路对话** 标签页。
2. 发送一个关于该对话的问题，它会结合对话内容作答。
3. 主对话中没有新增内容。
4. 旁路对话中不显示旁路对话的指示，而 fork 的 Trajectory 视图中可以看到它。
