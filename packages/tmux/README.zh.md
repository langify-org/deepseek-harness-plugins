# @langify-org/dsh-tmux

[English](README.md) | [日本語](README.ja.md) | 中文

用 tmux 为每个对话提供一个你和模型共享的终端。每个对话有自己的 tmux 会话，显示在 DeepSeek Harness 右侧边栏的 **tmux** 标签页中。会话在页面重新加载、关闭标签页和 DSH 重启后依然保留。模型在每轮开始时得知有哪些窗口，并通过可以运行任何 tmux 命令的工具在其中工作。

## 要求

- 带 Web UI 的 DSH `>=0.2.1-rc.5 <0.3.0-0`。
- DSH 主机上的 [`tmux`](https://github.com/tmux/tmux)，位于 `PATH` 中或由 `tmux` 设置指定。没有时，标签页会给出提示。tmux 无法在 Windows 主机上运行。
- 可选：用户 systemd（`systemd-run --user`）。有它时，tmux 服务器运行在自己的 scope 中，DSH 重启后窗口仍然保留。没有它时，服务器随 DSH 一起停止。

## 安装

```sh
dsh plugin --profile <profile> add @langify-org/dsh-tmux
```

在 DSH Web 和 Desktop 中，也可以从 **Plugins** 页面添加。

## 设置

| 设置     | 默认值                                   | 含义                                   |
| -------- | ---------------------------------------- | -------------------------------------- |
| `tmux`   | `tmux`                                   | tmux 可执行文件：`PATH` 中的名称或路径 |
| `socket` | `<DSH home>/tmux/socket`（bundle layer） | tmux 服务器的套接字                    |

## 使用

从右侧边栏打开 **tmux**，它显示当前对话的 tmux 会话。

- **原样使用你自己的 tmux 配置**，无论你的 tmux 在哪里查找它（默认为 `/etc/tmux.conf`、`~/.tmux.conf` 或 `~/.config/tmux/tmux.conf`）。插件只让 tmux 服务器在没有会话时也保持运行。
- **没有 tmux 配置时**，使用插件的默认设置：状态栏位于顶部，窗口以标签形式排列，并启用鼠标（点击窗口即可切换，滚轮可以滚动）。使用自己的配置时，加上 `set -g mouse on` 即可获得同样的效果。
- **右键**会交给 tmux，而不弹出浏览器菜单：按住右键移动到 tmux 菜单中的某一项再松开即可选择。按住 Shift 右键或长按，会弹出浏览器菜单。
- **复制**：用鼠标选择或在 tmux 的复制模式中复制，内容会进入你设备的剪贴板（tmux 通过 OSC 52 发送）。浏览器拒绝写入时，标签页会显示 **复制** 按钮。按住 Shift 拖动则使用浏览器自己的选择，按 Ctrl+C（Cmd+C）复制。
- **链接**：程序标记的链接（OSC 8，例如 `ls --hyperlink`）按住 Ctrl 或 Cmd 点击即可打开。
- **外观**跟随 DSH：浅色或深色的背景和文字颜色，以及终端字体和字号设置。
- **在手机上**，点击窗口即可切换，滑动可以回看 tmux 的历史（tmux 的复制模式，按 `q` 退出）。
- **多个标签页**，无论在一台设备还是多台设备上，都可以各自显示同一会话中的不同窗口。关闭标签页或连接中断后，会话及其中的程序继续运行；重新连接时，标签页会重新 attach。
- **归档对话**会结束其 tmux 会话。如果仍有程序在运行，归档对话框会把它们列为需要停止的工作。
- **从你自己的终端**，用 `tmux -S <DSH home>/tmux/socket attach -t '=dsh-<session id>'` 可以 attach 到同一会话。DSH 自带的终端标签页仍是普通 shell。

模型对终端的了解如下：

- **系统提示词**：在每个对话中说明共享终端、工具以及下面的通知格式。
- **每轮开始时**：窗口与上次所见不同时，模型会收到 `<tmux>` 通知，每个窗口一个 `<window id="@3" name="bash" path="~/repo" command="bash"/>`。空的 `<tmux>` 表示会话已关闭。没有会话的对话不会收到通知。
- **屏幕内容**：仅在模型自己读取窗口时。

模型有两个可以运行任何 tmux 命令的工具，套接字和目标由插件填入：

| 工具           | 参数                                  | 指向                                 |
| -------------- | ------------------------------------- | ------------------------------------ |
| `tmux_window`  | 窗口 id（必填）、窗格编号、命令、参数 | 该窗口或窗格，先确认它属于对话的会话 |
| `tmux_session` | 命令、参数                            | 对话的会话                           |

- 窗口用 id 指定，因为在 tmux 服务器运行期间 id 不会改变、也不会被重用；编号和名称可能会变。
- 例如，`tmux_window` 加 `capture-pane -p` 读取窗口，加 `send-keys` 向窗口输入；`tmux_session` 加 `new-window -d` 打开窗口并返回其 id；没有会话时会先创建。
- 新窗口和窗格在对话目录中启动。
- 模型不能自己写 `-t`，也不能给 `list-windows` 和 `list-panes` 传 `-a`，因此无法触及对话之外。
- 子代理调用时指向其对话的会话。

## 安全

- **tmux 在沙箱外运行**，因此会改变任何东西的 tmux 命令需要与沙箱外命令相同的许可：对话拥有完全访问权限时立即执行，否则会先显示 tmux 命令并询问你。无法询问的子代理只能在完全访问权限下执行。
- **只读不需要确认**：`capture-pane -p`、`list-windows`、`list-panes` 和 `show-options` 无需询问即可运行，除非参数中含有 `#(`（会运行 shell 命令的格式）或以 `;` 结尾（会开始另一条 tmux 命令）。
- **会话中的一切对模型都是可见的。** 不要在对话的终端中显示你不希望模型读到的秘密。
- **标签页的连接**与 DSH 自己的 API 请求一样经过检查：只有已登录此 DSH 的浏览器才能打开终端。
- **环境变量**：与 DSH 自己的终端一样，tmux 及其 shell 获得的是去掉名称包含 `KEY`、`PASSWORD`、`SECRET` 或 `TOKEN` 的变量以及 `DSH_*` 后的 DSH 环境。
- **隔离**：每个 DSH 主目录有自己的 tmux 服务器（`<DSH home>/tmux/socket`），不会触及你自己的 tmux 会话；每个对话只会得知它自己的会话。子代理不会得知。

## 工作原理

- **浏览器端**：加入 **tmux** 标签页，并把 tmux 以 OSC 52 发送的复制内容写入剪贴板。终端用固定版本并随插件打包的 [wterm](https://github.com/vercel-labs/wterm) 绘制，并通过专用的 WebSocket（`/langify-tmux`）与主机通信。
- **主机端的终端**：每个连接先像 DSH 的 API 请求一样经过检查，然后在需要时创建对话的 tmux 会话（`dsh-<session id>`），并在 DSH 的终端 subprocess provider 中运行 `tmux new-session -t '=dsh-<session id>'`。这是随连接结束的专用视图，因此各标签页可以显示不同的窗口。
- **主机端的其他部分**：
  - 在系统提示词中加入说明，并注册这两个工具。
  - 如果服务器不存在，以 `exit-empty off` 启动它（可能时放在独立的 systemd scope 中），并为标签页的终端类型加上 `hyperlinks` 功能，让 tmux 传递链接。
  - 询问服务器会查找哪些配置文件（`#{config_files}`），仅当它们都不存在时，才在服务器上设置默认值。
  - 通过 `agent/pre-step` 在一轮的第一步加入窗口列表。会话投影记录模型上次看到的内容，压缩后会重置，以便重新发送。
  - 为其他插件（例如 tasks）提供 `langifyTmux` 服务：在对话会话的新窗口中运行命令行，10 秒内 attach 的 tmux 标签页会显示该窗口。
  - 向归档对话框报告正在运行的程序，归档时结束会话。
  - 启动时结束期间已被归档或删除的对话的会话。

## 已知限制

- **服务器会继续运行**：移除插件后服务器不会停止，可用 `tmux -S <DSH home>/tmux/socket kill-server` 停止。
- **浅色主题下部分颜色较淡**：终端的 16 色与 DSH 自带终端相同，使用 xterm 的配色，在浅色背景上黄色和白色显得较淡。
- **手机上没有 Ctrl、Esc、Tab 和方向键**：手机键盘上没有这些键，标签页也没有添加。

## 在浏览器中验证

把 tmux 放进 `PATH`，在仓库根目录运行 `pnpm dev`：

1. 在对话中从右侧边栏打开 **tmux**。状态栏显示窗口 `0`。
2. 在终端中按住右键，移动到 tmux 菜单中的 **Horizontal Split** 再松开：窗口被分割，浏览器菜单不会弹出。
3. 让模型打开一个窗口，在其中运行 `echo hello` 并读回结果。它用 `tmux_session` 打开窗口（除非对话拥有完全访问权限，否则会先询问），用 `tmux_window` 输入命令，无需询问即可读回，并报告 `hello`。
4. 询问模型有哪些窗口。它会列出两个窗口及其目录。
5. 在终端中拖动选择一些文字：松开按键后，内容就在你的剪贴板里。
6. 重新加载页面：标签页重新 attach，显示同样的窗口。
7. 在某个窗口中运行 `sleep 600` 的同时归档对话：对话框列出一项 tmux 工作，停止后 tmux 会话结束。
