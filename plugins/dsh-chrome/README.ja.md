# dsh-chrome

[English](README.md) | 日本語 | [简体中文](README.zh.md)

DeepSeek Harness（DSH）の右サイドバーで、実際の Chrome をあなたとエージェントで共有します。

dsh-chrome は、DSH が動いているマシン上に、専用の Chrome を専用のプロファイルと専用の画面で起動します。DSH のセッションごとに、その Chrome のウィンドウが 1 つあります。セッションのサイドバーはそのウィンドウを、タブ、アドレスバー、メニュー、拡張機能のポップアップまで含めて表示し、あなたのポインター操作、キー入力、テキストを Chrome に送ります。セッションのエージェントは、ツールを使ってそのウィンドウのページを読み取り、操作します。並べて開いているセッションは、それぞれ自分のウィンドウを表示します。プロファイルには、ここで設定した内容や、お使いの Chrome からコピーした内容（サインイン済みのサイト、Chrome の同期、1Password などの拡張機能）が残ります。DSH Desktop からでも、tailnet 上のスマートフォンなど、別の場所のブラウザーで開いた DSH からでも、同じように使えます。

仕組みと理由は [docs/design.md](docs/design.md) を参照してください。

## 要件

- DSH 0.2（`>=0.2.1-rc.2 <0.3`）と、その Web クライアント。
- Linux。DSH が動いているマシンに次のものが必要です。
  - Google Chrome。Chrome 154 で動作を確認しています。
  - TigerVNC の `Xvnc`。Chrome が描画する X サーバーで、画面をメモリ上に保持し、VNC で提供します（Nix では `tigervnc`、Debian と Ubuntu では `tigervnc-standalone-server`）。
  - Openbox。Chrome のウィンドウをその画面いっぱいに保つウィンドウマネージャーです。
  - WebGL を使う場合は、マシンの GPU 用の Vulkan ドライバー（NVIDIA 製または Mesa 製）。
- macOS と Windows には対応していません。画面が X サーバーであるためです。

## インストール

1. プラグインをビルドします。このリポジトリで `nix build .#dsh-chrome` を実行すると、`result/langify-org-dsh-chrome-<version>.tgz` ができます。tarball は変わらない場所にコピーしてください。
2. DSH で **Plugins → Add plugin** を開き、tarball の絶対パスを指定します。そして DSH を完全に再起動します（Desktop の場合は、ウィンドウを閉じるだけでなく終了してください）。

以上です。Chrome は、Chrome タブを開いたとき、またはエージェントが最初にページを開いたときに起動します。設定は **Plugins** にあるこのプラグインのページで変更できます。このリポジトリのままプラグインを試すには、ルートで `pnpm dev` を実行します。プラグインをインストールした開発用の DSH が起動します。

dsh-chrome は、ファイルを DSH のホーム（DSH の他のデータと同じ場所）に保存します。`dsh` では `~/.dsh`、Desktop では DSH Desktop 自身のホーム、`DSH_HOME` を指定していればその場所です。プロファイルはその中の `dsh-chrome/chrome-profile` です。ホームごとに Chrome と画面が別になるので、ホームの異なる複数の DSH を同時に動かせます。

### 0.4 から

Chrome は、使っているディスプレイのピクセル比で描画するようになりました（`deviceScaleFactor` は `auto`）。多くのディスプレイでは、0.4 が描画して送っていたピクセル数の 4 分の 1 で済み、CPU の使用量も減ります（[design](docs/design.md#how-the-screen-reaches-the-sidebar) を参照）。`deviceScaleFactor` を設定していた場合は、その値のままです。Chrome はページの合成を CPU で行います。フレームごとに GPU から読み戻すより低コストなためです。WebGL は引き続き GPU で描画します。プロファイルのコピーは、どこまで進んだかを表示します。更新後は DSH のページを再読み込みしてください。サイドバーと設定ページは、このバージョンの仕様でしかプラグインと通信しません。

### 0.3 から

セッションごとに専用のウィンドウを持つようになり、セッション同士が互いの表示を奪うことはなくなりました。Chrome は自分のウィンドウを開かず、すべてのウィンドウを閉じても起動したままです。DSH の実行中に変更できる設定は、DSH の Plugins ページに移りました（[設定](#設定)を参照）。`cordis.patch.yml` に書いた設定は、これまでどおり有効です。Vulkan の GPU ドライバーがあるマシンでは、WebGL が使えるようになりました。

### 0.2 または 0.1 から

0.3 は、ページではなく Chrome のウィンドウ全体を表示し、専用の Chrome だけを実行します。

- 0.2 で使っていたプロファイル（`dsh-chrome/profiles/dedicated`）は、サインイン情報や拡張機能ごと `dsh-chrome/chrome-profile` に移ります。コネクター拡張機能とそのリレーは DSH のホームから削除されます。プロファイル内と、お使いの Chrome 内（`NativeMessagingHosts/io.github.langify_org.dsh_chrome.json`）にあるリレーの登録も、この DSH ホームのリレーを指しているものは削除されます。その後、Chrome がプロファイルからコネクターを自動的に取り除きます。
- お使いの Chrome は共有されなくなります。0.1 でコネクターをそこに読み込んでいた場合は、`chrome://extensions` で削除してください。
- 0.2 の設定（`dedicatedProfile`、`dailyProfile`、`defaultProfile`、`viewer`、`connectorSocketPath`、`nodeExecutable`）は無視されます。[設定](#設定)を参照してください。

## セットアップ

お使いの Chrome のサインイン情報、パスワード、ブックマーク、拡張機能を引き継ぐには、そのプロファイルのいずれかをコピーします。DSH で **Plugins** を開き、dsh-chrome のページの **Copy a profile of your Chrome** でプロファイルを選んで **Copy…** を押し、確認します。コピーすると dsh-chrome のプロファイルが置き換わります（置き換えられた側は、次のコピーまで `Default.before-copy` という名前で隣に残ります）。その間、Chrome は閉じ、すべてのセッションのウィンドウも閉じます。ページには、コピーがどこまで進んだかが表示されます。ファイルのコピー、データベースの検査、Chrome の終了とプロファイルの入れ替え、の順です。コピーの途中や終了後に開いたり再読み込みしたりしたページにも、その経過や結果が表示されます。DSH との接続が切れたり応答が途絶えたりしたページは、つなぎ直してそれを表示します。正確なコピーにするには、先にお使いの Chrome を閉じてください。起動中の Chrome は、直前の変更をまだ書き込んでいないことがあります。コピーしたプロファイルは、Chrome Sync に独立したデバイスとして参加します。

または、サイドバーの新しいタブのガイドから **Chrome** を開き、新しい Chrome と同じようにそこで設定します。

- エージェントに使わせたいサイトにサインインします。サインインは維持されます。
- 必要なら Chrome 自体にサインインします。同期により、ブックマーク、保存したパスワード、拡張機能が反映されます。
- Chrome ウェブストアから 1Password を追加し、サインインします。dsh-chrome は、このプロファイルの拡張機能が、お使いの Chrome の拡張機能と同じネイティブアプリに接続できるようにします。そのため 1Password の拡張機能は、お使いの Chrome のときと同じように、そのマシンで動いているデスクトップアプリを見つけられます（`shareNativeHosts`）。

## 使い方

| サイドバーでの操作 | |
| --- | --- |
| クリック、ドラッグ、スクロール、入力 | Chrome の画面を直接操作したときと同じように、Chrome に届きます。日本語などの入力方式による変換は DSH 側で行い、確定したテキストが Chrome に送られます。 |
| キーボードショートカット | キーの文字で Chrome に届きます。ラテン文字のないレイアウトでは US キーボードの文字で届くので、ロシア語キーボードでも Ctrl+C でコピーできます。macOS では ⌘ が Ctrl として働きます。AltGr や Option で選んだ文字は、その文字のまま入力されます。DSH を表示しているブラウザーが自分用に確保しているショートカット（Chrome では Ctrl+T、Ctrl+W、Ctrl+N）は使えません。その操作には Chrome 自身の ＋ と ✕ を使ってください。 |
| コピーと貼り付け | Chrome で行ったコピー（ショートカット、メニュー、ページのボタン）は、ブラウザーが許す場合（DSH を HTTPS または `localhost` で提供している場合）、お使いのクリップボードにも届きます。エージェントがコピーしたものは Chrome 内にとどまります。Ctrl+V（⌘V）は、お使いのクリップボードを貼り付けます。Chrome での直前のコピーがお使いのクリップボードに届かなかった場合は、Chrome のクリップボードを貼り付けます。 |
| 📷 / 📄 | Chrome のスクリーンショット、または見ているページのテキストを、次のメッセージに追加します。 |
| ⌨ | タッチスクリーン用のキーボードを表示します。タッチスクリーンでは、タップでクリックし、2 本指のドラッグでスクロールします。 |

Chrome 自身の UI も、ページと同じように画面に表示されます。メニュー、権限の確認、拡張機能のポップアップ、ダウンロード（DSH が動いているマシンの Downloads フォルダーに保存されます）、ページが開くダイアログなどです。ページが開くウィンドウ（サインイン用のポップアップなど）は、閉じるまで開いた元のウィンドウの上に表示されます。そのタイトルバーには閉じるボタンがあります。

セッションごとの Chrome タブには、そのセッション専用のウィンドウが表示されます。タブが表示されるとウィンドウが開き、必要なら Chrome も起動します。ウィンドウはタブの大きさになり、Chrome はタブのあるディスプレイのピクセル比で描画します。そのため、そのディスプレイで表示できるだけ鮮明になり、余分なピクセルは描きません。同じセッションの 2 つのタブ（2 つのブラウザーウィンドウ、またはスマートフォンなど）は同じウィンドウを表示し、最後に見たり操作したりしたほうのタブの大きさになります。もう一方は、収まるように拡大縮小して表示します。セッションのタブで入力したキーは、他のセッションのエージェントがそのセッション自身のウィンドウで作業している最中でも、そのセッションのウィンドウに届きます。Chrome でそのセッションの最後のタブを閉じると、Chrome タブに **Open a window** が表示されます。Chrome 自体は、DSH が停止するか、メニューから終了するまで動き続けます。終了した場合、タブには **Open Chrome** が表示され、同じプロファイルで Chrome を再び起動できます。

エージェントは次のツールを使えます。`chrome_pages`、`chrome_open`、`chrome_navigate`、`chrome_snapshot`、`chrome_screenshot`、`chrome_click`、`chrome_type`、`chrome_press`、`chrome_scroll`、`chrome_answer_dialog`、`chrome_close`、`chrome_ask_user` です。使えるのは、自分のセッションのページ、つまりエージェント自身が開いたページ、あなたがそのセッションのウィンドウで開いたページ、それらのページが開いたページです。他のセッションのページは、自分のものではありません。`chrome_open` は、セッションのウィンドウの最前面に新しいタブを開きます。操作を行うときは、あなたと同じように、まずそのページをそのウィンドウの最前面に出します。`chrome_ask_user` では、サインインやワンタイムコードの入力など、あなた自身にしてほしいことをエージェントが依頼します。依頼は Chrome の上に **Done** と **I can’t** とともに表示されます。エージェントの操作は、それによって開かれたダイアログやページを報告します。各ターンの開始時には、エージェントが使えるページと、あなたが見ているページが変わっていれば、それがエージェントに伝えられます。

## 設定

DSH の実行中に変更できる設定は、DSH の **Plugins** にある dsh-chrome のページにあります。`executable`、`deviceScaleFactor`、`announceAutomation`、`webgl`、`shareNativeHosts` です。ページは、プラグインの設定スキーマから、説明付きでこれらを描画します。設定は Chrome が次に起動するときに反映されます。Chrome タブにその旨が表示され、**Restart Chrome** が提示されます。これを押すと、すべてのセッションのウィンドウが閉じます。

すべての設定は、DSH プロファイルの `cordis.patch.yml` にも、プラグインの行の下に書けます。上記以外の設定はそこにしか書けず、変更するとプラグインが再起動します。

```yaml
- id: dsh-chrome
  config:
    deviceScaleFactor: 1
```

| 設定 | 既定値 | 意味 |
| --- | --- | --- |
| `executable` | `google-chrome-stable` | 実行する Chrome。 |
| `xvncExecutable` | `Xvnc` | TigerVNC の Xvnc。 |
| `windowManagerExecutable` | `openbox` | Openbox。 |
| `deviceScaleFactor` | `auto` | Chrome の 1 CSS ピクセルが、画面の何ピクセルを占めるか。`auto` は、Chrome の起動時に、最後に Chrome を要求したタブのディスプレイのピクセル比（4 分の 1 単位に丸め、1 から 4 まで。起動をまたいで保持され、どのタブもまだ要求していない間は 1）です。または、ディスプレイにかかわらず、4 分の 1 単位で 1 から 4 までの数値を指定できます。高密度ディスプレイでは 2 で鮮明になりますが、1 の 4 倍のピクセルを送ります。 |
| `announceAutomation` | `false` | Chrome が自動制御下にあること（`navigator.webdriver`）をページに知らせます。dsh-chrome はパイプで Chrome を制御しているので、Chrome は本来これを知らせます。知らせると Google がサインインを拒否し、他のサイトからはボットと見なされることがあります。[セキュリティ](#セキュリティ)を参照してください。 |
| `webgl` | `gpu` | Chrome が WebGL をどう描画するか。`gpu` は Vulkan 経由でお使いの GPU で描画します（Vulkan ドライバーがなければ WebGL なし）。`gpu-or-cpu` は GPU で、できなければ CPU で描画します。CPU 描画は遅く、悪意あるページの標的にもなりやすいため、Chrome は自分では許可しません。`off` は Chrome の判断に任せます。この画面では WebGL なしになります。 |
| `profileDir` | DSH ホームの `dsh-chrome/chrome-profile` | Chrome のプロファイル（ユーザーデータディレクトリ）。 |
| `shareNativeHosts` | `true` | ネイティブメッセージングのマニフェストをリンクすることで、プロファイルの拡張機能が、お使いの Chrome の拡張機能と同じネイティブアプリに接続できるようにします。 |
| `userChromeDir` | `~/.config/google-chrome` | お使いの Chrome のユーザーデータディレクトリ。そのネイティブアプリが共有され、そのプロファイルがコピーできます。 |
| `dataDir` | DSH ホームの `dsh-chrome` | dsh-chrome が起動をまたいで記録する内容の保存先。 |
| `runtimeDir` | `$XDG_RUNTIME_DIR/dsh-chrome/<DSH ホームのダイジェスト>`。`XDG_RUNTIME_DIR` がなければ一時ディレクトリ内 | 画面の VNC ソケットと X クッキーの置き場所。このディレクトリと、それを含むディレクトリは、あなたの所有でなければなりません。dsh-chrome はこれを非公開にし、他のユーザーのものは拒否します。 |

ツールとターン開始時の読み取りは別々の行になっています。どちらか一方だけを無効にできます。

```yaml
- id: dsh-chrome-tools
  disabled: true
- id: dsh-chrome-context
  disabled: true
```

## 制限事項

- Chrome が自分では描画しないものは、DSH が動いているマシンのデスクトップに任せます。ページのファイル選択ダイアログは、サイドバーではなくそこで開き（GNOME と KDE ではデスクトップポータル経由）、サイトの通知も同様です。他のデバイスからのファイルのアップロードは、まだできません。
- 入力方式で変換したテキストは、ASCII 以外の文字（日本語、アクセント付き文字、絵文字）を含む場合、貼り付けとして Chrome に届きます。そのため Chrome の画面のクリップボードにもなります。キー、ASCII、1 文字は入力として送られます。256 KiB（Xvnc の上限）を超える貼り付けは届きません。
- セッションのウィンドウにはタスクバーがありません。同じセッションの 2 つ目のウィンドウは 1 つ目を覆ってしまうので、タブで使ってください。
- 同時に表示しているセッションのウィンドウは、1 つの画面に横に並びます。X の制約で画面の幅は最大 16384 ピクセルです。既定の大きさでは 5 セッション前後、サイドバーの大きさならもっと多くなります。それを超えるセッションには、空きがないと表示されます。どのタブにも表示されていないセッション（サブエージェントを含む）のウィンドウは、タブに表示されるまで脇にまとめて置かれます。
- セッションのウィンドウの大きさが変わるとき、そのタブに別のセッションのウィンドウが一瞬表示されることがあります。
- WebGL には GPU 用の Vulkan ドライバーが必要です。ない場合、`webgl` が `gpu-or-cpu` でなければ、ページは WebGL を使えません。
- エージェントの操作とあなたのキー入力は、キーボードを交代で使います。ウィンドウがキーボードを失うとメニューを閉じるページは、あなたが別のセッションで入力している間にメニューを閉じます。
- 画面には音声がありません。
- サブエージェントが開くページは、あなたのセッションではなくサブエージェントのセッションに属し、専用のウィンドウで開きます。
- DSH で変更した設定は、Chrome が次に起動するときに反映されます。その際、すべてのセッションのウィンドウが閉じます。
- Chrome は、すべてのセッションで 1 つの倍率で描画します。`auto` では、Chrome の起動時に最後に Chrome を要求したタブ（開いたタブ、開いたページ、再起動）のディスプレイのピクセル比になり、DSH の起動をまたいで保持されます。ピクセル比の異なるディスプレイのタブでは、Chrome が拡大縮小されて表示され、**Restart Chrome** が提示されます。これを押すと、そのタブのピクセル比で Chrome が起動します。

## セキュリティ

- あなたの DSH の Web UI を使える人は、DSH のターミナルを使えるのと同じように、この Chrome を、プロファイル内のすべてのサインインごと使えます。
- TCP ポートは開きません。dsh-chrome は、Chrome を起動するときに渡すパイプ（`--remote-debugging-pipe`）で Chrome を制御します。このパイプを持つのは dsh-chrome だけです。Xvnc は画面を Unix ソケットだけで提供し（`-rfbport -1`、`-nolisten tcp`）、パスワードはなく、あなたの OS ユーザーだけが入れるディレクトリに置きます。X サーバーとしては、クッキー（そのディレクトリの `Xauthority`）を渡されたプログラム、つまり Openbox と Chrome だけを受け入れます。あなたのユーザーの他のプロセスは、すでにプロファイルを読めるので、信頼されます。
- サイドバーは、DSH 自身の認証済み WebSocket を通して画面に接続します。許可の仕方は DSH の `/api` と同じです。
- dsh-chrome が Chrome に送るのは、使う CDP コマンドだけです。エージェントのツールが読み取り、操作できるのは Web ページだけです。Chrome 自身のページ（設定、保存したパスワード）、拡張機能のページ、ローカルファイルは、あなたが開いていても対象外です。Cookie ストア、ネットワークトラフィック、ページ上の他の拡張機能（パスワードマネージャーなど）のコードも対象外です。
- ページには、Chrome が自動制御下にあることを知らせません。`navigator.webdriver` は、手で使う Chrome と同じく false です。Chrome はパイプで制御されているとこれを設定し、Google のサインインはそのブラウザーを拒否します（"This browser or app may not be secure"）。他のサイトのボット判定も同様で、あなた自身が操作している場合でも拒否されます。そのため、サイト側はエージェントが操作していることも見分けられません。エージェントは人の速さで、あなたのセッション内で、あなたに代わって操作します。利用しているサイトが必要とする場合は、`announceAutomation` を設定して知らせてください。そのために必要なフラグ `--disable-blink-features=AutomationControlled` について、Chrome は起動時に開くウィンドウにバー（"unsupported command-line flag"）で警告します。dsh-chrome ではそのウィンドウを開かず、各セッションのウィンドウを自分で開くので、このバーは表示されません。このフラグは `navigator.webdriver` 以外を何も変えません。
- `shareNativeHosts` を有効にすると、プロファイルの拡張機能は、お使いの Chrome の拡張機能が起動できるネイティブアプリを起動できます。各アプリのマニフェストは、受け入れる拡張機能を引き続き限定しています。
- プロファイルのコピーは、お使いの Chrome のプロファイルを読み、dsh-chrome のプロファイルにだけ書き込みます。dsh-chrome の Chrome は、キーリングが Chrome 用に保持している鍵で、サインイン情報とパスワードを読みます。
- セッションは、人と人の間の境界ではありません。DSH を使える人は、すべてのセッションの Chrome ウィンドウを使えます。
- エージェントは、Chrome を通して DSH 自身の Web UI を開くことも、それを表示するページ（フレーム内を含む）を操作することもできません。DSH にサインイン済みのプロファイルでは、そうしないとエージェントが自分の操作を自分で承認できてしまうためです。DSH は、それが提供しているアドレスで判別します。別のローカルポートのプロキシ越しの DSH は判別されません。
- ページは Web コンテンツです。スナップショット、ページのテキスト、ダイアログ、スクリーンショットは、信頼できないものと明示されてエージェントに届き、タイトルは引用符で囲んで短縮されます。エージェントには、パスワード、コード、カード番号を決して入力せず、代わりにあなたに尋ねるよう指示しています。ただし、モデルが入力欄をどう扱うかまでは、プラグインでは強制できません。

## トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| "Xvnc (Xvnc) was not found" | DSH の環境から見つかる場所に TigerVNC をインストールするか、`xvncExecutable` を設定してください。 |
| "the window manager (openbox) was not found" | Openbox をインストールするか、`windowManagerExecutable` を設定してください。 |
| "Chrome (google-chrome-stable) was not found" | Google Chrome をインストールするか、`executable` を設定してください。 |
| Google: "This browser or app may not be secure" | `announceAutomation` がオフになっています（既定値です）。 |
| Chrome が起動してすぐ終了する | 別の Chrome がこのプロファイルを使っている可能性があります。dsh-chrome の Chrome は 1 つしか動きません。`--user-data-dir` が `profileDir` である `chrome` を探してください。 |
| ページで WebGL が使えない | GPU 用の Vulkan ドライバーが DSH の環境から見つかる場所にインストールされているか（`vulkaninfo`）、または `webgl` が `gpu-or-cpu` か確認してください。設定は Chrome が次に起動するときに反映されます。 |
| "the screen has no room for another session's Chrome" | もう見ていないセッションの Chrome タブを閉じるか、サイドバーを狭くしてください。 |
| コピーしたプロファイルがサインインされていない | Chrome の鍵を保持するキーリング（"Chrome Safe Storage"）のロックが解除されているか、意図したプロファイルをコピーしたかを確認してください。置き換えられたプロファイルは、`profileDir` の `Default.before-copy` です。 |
| 1Password の拡張機能がアプリに接続できない | デスクトップアプリが DSH の動いているマシンで動作していること、Chrome 向けのブラウザー連携がオンであること、`~/.config/google-chrome/NativeMessagingHosts/com.1password.1password.json` が存在することを確認してください。 |

## 開発

リポジトリのルートで `pnpm install` を実行し、続けて `pnpm dev` を実行すると、開発用の DSH でプラグインを試せます。このディレクトリでは、`pnpm build`、`pnpm test`（ユニット）、`pnpm test:compat`（ビルド後に DSH のパッケージに対して実行）、`pnpm test:integration` を使います。統合テストは、Openbox 配下の Xvnc 上で、一時的なプロファイルを使って Chrome を起動します。テストの対象は、DSH 自身のスキーマ検証器で確認するエージェントのツール、VNC クライアントが見て操作するのと同じ形での画面上の Chrome、ビルド済みのサイドバーモジュールから、ヘッドレス Chrome 内の noVNC、DSH の Web サーバーを経て Chrome に至る経路全体（2 つのセッションのタブを同時に使います）、そして設定ページです。テストプロセスごとに、専用の DSH ホームが用意されます。ファイルは 1 つずつ実行します。それぞれが Chrome とその画面を動かし、同時に実行すると CPU を取り合い、ページのフォーカスや入力を待つ処理がそれに耐えられないためです。

`src/` は、コードが動く場所ごとに分かれ、Host の中ではさらに各部分の役割ごとに分かれています。どの部分がどの部分を import してよいかは、[test/unit/dependencies.test.ts](test/unit/dependencies.test.ts) で定義され、検査されています。

サイドバーは [noVNC](https://github.com/novnc/noVNC) 1.7.0（MPL-2.0）をバンドルしています。そのライセンスはパッケージの `dist/licenses/` に含まれています。パッチ（リポジトリルートの `patches/`）は、DSH のモジュールローダーが実行できない noVNC のトップレベルの `await` を 1 つ取り除き、画面の 1 つの領域だけを表示する機能（`viewRegion`）を追加します。タブはこれを使って、そのセッションの部分を表示します。
